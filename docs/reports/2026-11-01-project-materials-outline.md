# 整项目资料识别与大纲剧情节点交付

用户希望完整导入旧作时自动识别大纲、人物等附属文件，汇总人物档案，并能从已有大纲反推具体剧情供情节线与无限白板展示；保留单独上传人物档案。实现位于 `codex/project-materials-outline`，基于 master `503e7c2`，当前代理独立实现、自审与验收，未派生代理。

## 实现

- TXT、Markdown、JSON及文件夹导入；正文与人物/大纲/设定资料分流。支持Markdown章标题，带章标题的大纲也不会混入正文。预览可逐文件纠正分类，不支持、空白、过大文件明确说明。
- 安全相对目录保留，`人物/说明.md` 与 `大纲/说明.md` 不相互覆盖；沿用文件事务对越界和符号链接的保护。原有人物档案单独上传保留。
- 导入先保存，勾选自动整理时先归并人物/关系，再提取大纲/情节线，最终保存一份未确认方案。任一步失败都保留已导入原稿，作者可手动重新整理；没有自动确认、采用或隐藏重试。
- 两阶段使用只读资料与候选工具，在执行层拒绝未提供的工具。材料换版中断合并，不保存混合版本；人物表明确命名的条目必须归并或在摘要说明排除，清单遵守同一上下文上限。
- 大纲节点独立保存为 `outline-nodes.json`，携带文件名和逐字出处。章号仅在出处明确标注时填写；目录标题不能支撑扩写细节；具有具体段落的分章大纲检查覆盖，不允许只交付开篇而漏掉终章。
- 确认事务、引用删除保护、重开与备份兼容。节点本身不生成 `plot_event`、章计划或正文，不影响正式情节推进统计；新增人物的既有确定性正文出场扫描与资料关系声明仍保留。
- 情节线展示具体节点与资料出处，白板区分已写/未来计划/资料。未标章号节点按资料顺序显示，标注“尚未核对正文”，不伪造正文锚点或原文跳转。
