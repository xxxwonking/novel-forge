# 对话写作要求随章节任务保存

> 当前代理使用 executing-plans 执行并复核；用户已授权继续真实流程及必要修复，禁止独立 Agent。

**Goal:** 修复主对话里的本轮写作要求没有进入 C4 的问题，并保证任务恢复、重复请求使用一致的要求。

**Architecture:** 复用章节任务的 `writeContext`，只在创建任务时保存本轮作者请求，在 C4 任务正文中明确标为写作要求。正式资料、计划和采用继续由原业务入口管理；本轮对话不会作为新的正式故事事实。历史任务不补入后来的请求。

**Tech Stack:** TypeScript、现有 ProjectSession / ChapterWriter / LangGraph、Vitest。

## 证据与选择

真实验收 `23-say` 明确要求另做试蜡、保留原封、避免直接推断开箱。主 Agent 读取第二章和第三章计划后直接 `write_next_chapter`；`call-55-request.json` 包含完整 ch2d4，却没有本轮请求。不是前章正文丢失。

只改提示要求模型转存计划仍可能遗漏；把每次临时写法都写成正式设定会混淆事实边界。采用随任务冻结作者原请求的办法，并让创作模型只处理其中与本章写作有关的内容，不把采用、导出等操作要求写进小说。
