# 完整项目资料识别与大纲剧情节点 Implementation Plan

> 按项目既定协作约定，当前代理独立执行、测试及复核，不派生代理；用户已授权实施，计划保存后直接执行。

**Goal:** 完整文件夹导入时识别正文与附属资料，自动汇总人物/关系/情节线/大纲节点为待确认方案，并在确认后供情节线和白板展示，保留单独上传能力。

**Architecture:** 保留同步正文入库与资料保存，UI在导入成功后显式显示资料整理阶段并调用受限起草，不自动确认或重试。大纲节点独立存储，不制造正文事件或章计划；复用资料提案、确认事务、来源校验及备份机制。章号可空，资料出处必须逐字可验证；白板与情节线区分资料推断、未来计划、正文已核实。

**Tech Stack:** React19/TypeScript/shadcn/Radix，现有Node服务与事务文件存储、Vitest；无新依赖，沿用Node24.20.0。

## Chunk 1: 导入分类与自动汇总

- [x] 阅读现有split/material/preparation/import UI及测试；写回归覆盖带章节标记的大纲、纯资料导入、单个资料、Markdown及文件夹路径。
- [x] 实现共享分类与输入文件支持，资料不再误当正文或被静默忽略；预览显示识别结果、跳过原因及可纠正的分类。
- [x] 测试导入协调：先入库、资料存在时自动起草、只产候选、模型失败保留导入且提供重试，无资料不调用模型。
- [x] 保留人物档案单独上传入口；导入结果清楚区分正文、已保存资料、待确认与起草失败。
