# 写作建议随具体稿件采用的实施计划

> **执行方式：** 当前代理按 `superpowers:executing-plans`、TDD 和完成前验证实施并自审；用户禁止独立 Agent。此计划落实既定用户流程 §4.3、§6.2–6.3，不重新请求已经提供的开发授权。

**Goal:** 用户能在章节结果看清 C4 提出的资料/未来伏笔建议，明确选择后随具体版本采用；未选建议不自动应用，失败不会产生部分正式状态。

**Architecture:** 在现有采用请求增加可选的建议索引及稿件凭据，纯函数构造可预览的字段变化和规划事件，再由 Session 的同一个文件事务确认依赖、检查、采用正文并应用所选项。建议不创建独立写作任务；正式故事事实继续来自 C5，未来伏笔使用 `P4_outline`。已确认资料/规划属于作者决定，不因重写一章而自动撤销。

**Tech Stack:** TypeScript、现有 ProjectSession / DraftStore / 文件事务、React、Vitest、Playwright。

## 设计与取舍

- 沿用结果页中的建议区，但将选择摘要放在采用操作附近。默认不勾选；“采用这一版”只应用明确选择的索引。自动接受全部建议会扩大原指令范围，另存一份无关联资料方案则无法保证同次采用的一致性，因此采用请求直接携带选择。
- 预览返回人物名、受支持字段、原值、新值与原因；不存在/重名人物、非资料字段、非法结构和既有不可变属性冲突都给出不能选择的具体原因。
- 资料字段以明确的白名单及结构解析处理，不执行任意点路径赋值。支持人物 profile 的文字、列表、外貌属性，以及 speech 的受控字段；不允许改 ID、姓名、来源、派生 state。
- 伏笔建议必须是将来安排，保存已确认的 label / intent / weight / expectedBy；没有正文依据时不造出“已埋设”或“已兑现”。分配不与候选或历史事件重复的 ID。
- 采用前核对 revisionToken、来源及索引。候选人物资料会进入同样的 C6 检查；任何必须处理项阻止整次采用，原稿和正式资料不被部分修改。正文、C5、资料、计划事件、采用收据和正式版本映射同事务落盘。
- 收据记录被选择的索引和具体前后值。重试同一次采用不重复增加规划；采用后再发送不同选择会被拒绝。最新章再编辑时，已经应用的建议不重复出现在新候选的待采用列表。
- 普通查看、生成、暂停/恢复或不带选择的采用不应用建议。检查并采用可冻结同次选择；只检查不接受建议。主 Agent 和按钮调用同一入口。
- 未来规划进入资料页及结构视图，下一阶段继续核对规划变成正文埋设时的 ID 与状态衔接。
